02 / PURPOSE

训练目的

不以训练 reward 的最高点作为结论，而是回答四个明确问题。

P1SFT 的作用验证示范轨迹能否提高工具格式、证据引用与中文讲解的稳定性。
P2Direct RL验证初始模型是否能仅依靠环境反馈学会工具选择、搜索与停止策略。
P3顺序协同检验 SFT 是否把策略带入有效探索区域，从而提升后续 GRPO 的效率与上限。
P4规模效应比较 4B 与 9B 的收益、稳定性、显存、延迟和单位成功成本。

SFT 能力边界 这批开放 SFT 主要学习工具协议、给定证据下的推理、grounded QA 和中文讲解，不把它描述成已经学会 Search Policy。何时搜索、如何改写 query、读取什么以及何时停止，主要由后续原生 Agent 轨迹与 RL 学习。
04 / RL DATA

Task，而非答案轨迹

RL 从开放数据的不重叠 source group 中抽取 Task、tool schema、corpus 和 verifier。模型通过当前 StudyHub 的 Hermes Agent Harness 与冻结工具环境生成轨迹；开放数据中的既有 Assistant / Tool 轨迹不作为 RL target。

06 / EXECUTION

先 4B，后 9B

统计设计仍是完整的 2 × 2 × 2；工程上先用 4B 验证数据、环境、Reward 和对照关系，再以同一协议复现到 9B。

G0固定 4B/9B revision、全局 group split、TaskSpec、环境和 Reward。
G1 · 4B评测 B0；只做一次 SFT，保存 B1 并从同一 checkpoint 分叉 B3。
G2 · Gate先跑 1-step / 8-task Gate，确认 Hermes、工具、Reward、LoRA 更新和 GPU guard 全链路。
G3 · Pilot再跑 10-step Smoke 与 200-task Pilot，检查 group reward 方差、无 oracle 泄漏与 reward hacking。
G4 · 4B完成 4B 正式 2 × 2 与多 seed 评测，验证主效应和交互作用。
G5 · 9B用相同 Task、环境、预算和协议复现 9B，最后联合分析八组模型。
