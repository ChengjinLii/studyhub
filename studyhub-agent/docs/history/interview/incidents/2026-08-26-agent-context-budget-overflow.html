最小修复

每次调用做精确计数

不依赖字符数或粗略 token 估算；计数器使用与实际模型请求一致的 template、tools 和 tokenizer。

将收尾阈值写入运行时

达到 80% 窗口或 model-turn budget 时，不再开放工具，只允许基于已有 observation 作答。

保留 768-token 答案空间

从 256 提高到 768，使“进入收尾”与“答案可以完整结束”成为两个独立约束。

只在强制收尾关闭 thinking

常规推理和工具选择保持原配方；仅 finalization request 设 enable_thinking=false，避免全局改变策略能力。

失败时 fail closed

若压缩或收尾仍不能满足精确预算，写入明确 runtime error 并 hard gate，不把截断文本当作正常答案。

把上下文预算写入证据

逐 rollout 保存 pre-guard、sent prompt、压缩量、forced-final 原因、thinking 状态和 guard failure。

为什么没有采用更大的改动

  • 没有全局关闭 thinking：这会改变所有 Search/Read 决策，不再是上下文修复。
  • 没有把训练序列直接改到 8,192：rollout server 的上下文容量不等于 PPO 训练序列配方，扩大窗口也会提高显存与计算成本。
  • 没有粗暴删除全部 tool observation：证据会被破坏，Reward 和引用校验失去意义。
  • 没有用降低 max turns 掩盖问题：任务预算已经单独审计，输入预算仍需在真实渲染后强制执行。
