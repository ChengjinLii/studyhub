面试问题

讲一个 Agent 基线评测中，模型服务正常但所有任务都没有真正 rollout 的故障。你如何区分 Infra failure 与 policy failure？

30 秒回答

双 H100 上两个 Qwen3.5-9B SGLang 副本都成功加载，但 Hermes 初始化前检查到服务只报告 32,768 token，而 Hermes 的固定最低合同是 64,000 token，因此 20 个能力样本全部在模型调用前失败。评测器将带 runtime error 的 episode 全部标为 INFRA_EXCLUDED，没有把它们算成模型失败。原模型支持 262,144 token，所以修复是把 SGLang 服务窗口提高到 65,536，并加回归测试，而不是绕过 Hermes 检查。

为什么不修改 Hermes

Hermes 的 64K 下限是 policy harness 的公开运行合同，工具 schema 与系统前缀需要稳定的上下文预算。模型本身支持更长窗口且显存仍有余量，因此修改服务配置是更小、更符合上游语义的修复；跳过检查会制造一个不可比较的自定义 Hermes 分支。

残余风险

本次只证明了故障隔离与服务配置问题。修复后的 Gate 仍需验证真实 tool call、Observation 回注、唯一 system prompt、完整 20 类能力覆盖及零 Infra exclusion，才能进入 Regression 和 Development。
