RL Task Budget
Contract

运行时已经降到 6 个 model turns，但 RL v1 仍声明 10 steps / 8 calls；QASPER adapter 又把不同 annotator 的答案与 evidence 合并，使部分任务从定义上不可完成。

35V1 TASKS OVER 6 TURNS
15V1 TASKS OVER TOOL BUDGET
2,400V2 TASKS AUDITED
0V2 BUDGET VIOLATIONS
30 秒回答。 静态审计发现运行时和数据任务预算由两处独立配置，且 QASPER 多标注被错误做并集，导致 35 条参考路径超过 6 turns、15 条超过工具预算。修复后以 budget_contract.py 作为单一事实源，QASPER 选择一个 deterministic canonical annotation，并在构建、verifier、preflight 和单测中独立重算可行性；v2 的 2,400 条任务全部通过。

问题

Reference path = one search + one read per required source + one final model turn Runtime: max 6 model turns / 6 tool calls V1 QASPER: answer/evidence union across annotators → up to 21 gold sources

静态“有答案”不等于环境中可完成。若 verifier 要求读取的 source 数量超过公开预算，任何 policy 都会被惩罚；RL 会把数据合同错误当作策略失败，污染 Reward 分布和 zero-variance 诊断。

排除的替代解释

并行 Tool Call 能解决？不能解决 15 条调用总数已超过公开预算的任务，也不能假设 search/read 可以任意并行。
模型可以少读 source？Reward v2 要求隐藏 gold evidence set；跳过 source 不能被当作参考成功路径。
把 max_turns 改回 10？仍保留 15 条 tool-budget 违规和 annotation mismatch，并显著提高 sequence cost。

根因

  • Runtime 与 dataset task budget 独立配置，没有共享合同。
  • QASPER answer 与 evidence 跨 annotator 做并集，而不是保持 annotation binding。
  • 构建阶段没有 fail-closed feasibility audit，将 verifier 要求与公开预算比较。

修复与回归

training/rl/budget_contract.py 统一定义 6 turns / 6 calls。每条任务保存隐藏预算合同；构建器拒绝参考路径超限的 candidate。QASPER adapter 选择一个规范 annotation，并只绑定该 annotation 的 evidence；Function Calling 保留连续 assistant tool rounds，并额外计入 final-answer turn。

v2 生成 2,000 train / 400 validation：SFT overlap=0、train/validation group overlap=0、公开 Oracle 字段为空，参考 turns 与 calls 均在 [1,6] 范围内。旧 v1 Smoke 只作为 runtime 诊断，不进入 v2 paired comparison。

残余风险

参考路径是保守可行性证明，不保证模型实际能完成。模型可能通过并行 function calls 减少 turns，也可能因 query reformulation 消耗更多步骤；Pilot 仍必须报告 budget exhaustion、premature final、tool loop、family success 和 sequence truncation。

3 分钟回答结构。
Runtime 配方变化 → 静态审计发现 6-turn 合同与 v1 task 不一致 → 追到 QASPER annotation union → 排除并行调用与简单放宽预算 → 建立共享 budget contract 和 canonical binding → 重建 2,400 条 v2 数据 → 全量 audit/preflight/单测通过 → 旧 GPU 结果不复用 → 在 Pilot 继续观察实际预算失败。
