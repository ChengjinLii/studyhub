# StudyHub 独立知识产品设计

日期：2026-10-16。

本方案接替“校园资料目录工具 + 网站规则问答”的产品方向。保留现有执行器和历史回归基线，新的默认入口面向文档知识库、RAG 问答与多步 Agent。本文中的设计目标和当前实现分开记录。

---

## 产品边界

产品可独立安装、导入文档、建立索引、检索与问答。网站只是同一仓库中的另一个产品，不是本产品的依赖。

- 知识库和文档使用独立标识、数据目录及配置。
- 不读取网站环境文件，不调用站内 API，不读取主站 MySQL 或生产 OSS。
- 文档范围由调用方在服务端构造，不从模型参数推导或扩大。
- 现阶段资料使用本地文件和合成样本。真实资料导入需要另行确认。
- 模型服务是显式配置的外部依赖，可使用独立本地服务，不自动启动模型或占用 GPU。

新入口使用仅含主体类型与身份标识的 `KnowledgePrincipal`；旧快照的购买和所有权字段不出现在新任务的主体记录中。文档访问范围由独立 `KnowledgeScope` 管理。

FastAPI、Next.js、MySQL 是主站现有技术，不构成本产品选型约束。第一阶段延续 Python，复用已有运行契约与模型客户端；后续 UI、持久化数据库和任务队列按独立产品选择。

## 替换关系

| 原方案 | 新方案 | 历史兼容方式 |
| --- | --- | --- |
| 资料元数据 BM25 | 正文关键词召回 + 可选向量召回 + RRF + 可选重排 | 原 BM25 仅在 `ReplayEnvironment` 回归中保留 |
| 搜索、推荐、平台政策、购买权限等业务语义 | 查知识、读文档、列文档三项工具与独立知识范围 | 原八项工具不进入新 CLI 的模型提示 |
| 预览页字符串 | 来源版本、原文片段、行号及字符区间 | 不伪造 PDF 页码，不将 Markdown 行号描述为页码 |
| 页码格式引用 | 与内容和版本绑定的片段引用 | 新格式 `[k_片段标识]`；旧 `[资料ID:页码]` 仅用于旧环境 |
| 引用纠正耗尽后接受失败答案 | 无效引用继续反馈，预算耗尽时无成功最终答案 | 不修改历史五种架构的回归行为 |
| 所有问答都运行多步循环 | 简单问答走固定 RAG，多步任务显式选择 Agent | 新入口 `ask --mode rag/agent` |
| 未配置语义检索时含糊降级 | 返回 requested/effective mode 与降级原因；显式 semantic 无模型则报错 | 检索服务故障始终不是“未找到” |
| 先围绕网站建立 AgentBench，再开发后训练 | 先评测解析、检索与证据，再评测 Agent 增益 | 原评测设计作为历史方案，不继续扩充网站业务假设 |

`EpisodeRunner`、真实 token 预算、消息契约、命名模型客户端和原始轨迹记录保持复用，不因重设计而建立第二套 Agent 循环。

## 分层结构

```text
CLI / 后续独立 API 和 UI
    |
    +-- 固定 RAG：检索 -> 证据装配 -> 一次生成 -> 引用检查
    |
    +-- Agent：EpisodeRunner -> 三项知识工具 -> 引用检查与纠正
                                  |
                       KnowledgeRetriever
                    /         |          \
               BM25       Embedding      Reranker
                    \         |          /
                      版本化 Corpus 快照
                              |
                 本地文本 -> 结构分块 -> 原子发布
```

依赖方向由 import-linter 约束。`knowledge` 不依赖 `runtime`、`architectures`、`environments` 或网站工具；`contracts` 存放共享模型。新知识工具通过环境协议接入原执行器。

### 文档与证据

- `Document`：知识库、来源标识、标题、原文、内容哈希。来源标识与知识库决定稳定文档 ID。
- `Chunk`：原文切片、独立 ID、所属文档版本、父窗口、顺序、字符和行号范围、标题路径。
- `Evidence`：模型实际见到的原文及来源定位；不包含本机路径、隐藏文档、模型密钥。
- `Corpus`：校验文档和片段身份、版本、原文切片、行号、重复 ID；整体具有内容指纹。

片段 ID 由文档 ID、内容版本、字符范围和标题路径共同生成。重导入相同来源时替换旧版本全部片段；旧引用不能命中新版本。重复导入保持确定性。快照原子替换失败时保留上一版。

父窗口只用于分块组织；邻域阅读返回逐个子片段，不生成冒充原文的父级引用。原文不做破坏性清洗，公式和代码的语义正文保留。

### 检索约束

1. 确定调用方知识库与文档范围，二者取交集；显式空范围表示不可见。
2. 在该范围内运行正文 BM25 和可选向量召回，每路最多 50 个候选。
3. 混合模式按 RRF 排名融合，固定 `k=60`，稳定处理平分。
4. 可选重排只看到授权候选。拒绝不完整索引、维数不一致、零向量、NaN 和无穷分数。
5. 输出按数量和字符预算裁剪，整块省略而不是截短后沿用原引用。
6. 记录有效检索模式、模型身份、语料指纹与降级原因。排序分数不是概率。

未配置 embedding 时，hybrid 明确降为 keyword；显式 semantic 则拒绝运行。配置过的模型服务若失败，不自动伪装为关键词成功或无答案。

第一阶段 query embedding 与文档向量通过显式 HTTP 端点计算，文档向量在单个检索实例内按片段缓存。长期向量索引、多进程共享、增量写入与索引版本切换属于后续持久化阶段，不把进程内缓存描述为生产向量数据库。

### RAG 与 Agent

固定 RAG 复用策略客户端，但不启用工具、不运行规划或自检循环。没有检索证据时不请求生成模型；超出真实 token 预算则明确返回预算状态。无效或缺失片段引用不会作为成功答案返回。

Agent 只得到三项知识工具。模型无法选择任意数据库、网站接口或扩大知识库范围；文档中的指令按不可信数据处理。引用检查失败后继续反馈，最终成功必须通过引用身份检查。

当前确定性引用检查验证“引用属于实际展示的当前版本原文”，不代替事实支持关系判定。后续增加带人工标注支持片段的评测，不能把引用存在率宣传成回答准确率。

## 验收顺序

1. 文本解析与定位：覆盖率、Unicode/换行、公式表格保真、版本更新及失败恢复。
2. 检索：同语料下比较正文 BM25、向量、混合、混合加重排，报告 Recall@K、MRR 和延迟。
3. 问答：核对答案支持片段、错误引用、不可回答、提示注入、跨库隔离。
4. Agent：与同模型、同知识服务的固定 RAG 配对比较多文档任务完成率、回合和成本。
5. 产品服务化：独立 API/UI、隔离解析 Worker、任务状态、停止与重试、持久化检索。
6. 协议与数据集稳定后再设计 SFT/RL，避免为即将淘汰的业务工具训练模型。

## 技术选择原则

优先参考经过源码与测试核对的机制，而不是照搬上游所有基础设施。轻量阶段使用经过校验的本地快照，后续再对比直接运行 WeKnora 知识服务与自有持久化实现的效果和维护成本。主站技术栈、订单和生产权限都不参与该比较。

## 本轮验收记录

验证环境为独立 Python 3.12 环境，包的 wheel 安装另外使用干净环境验证。

| 检查 | 结果 |
| --- | --- |
| 全套测试 | 385 项通过，包括原有回归与新增 68 项知识链路测试 |
| 包覆盖率 | 97.28% |
| 静态与分层检查 | Ruff、三项 import-linter 契约、Git 空白检查通过 |
| 文档检查 | 8 份 Markdown 的 64 个本地链接和代码围栏通过 |
| 独立安装 | wheel 构建、非 editable 安装及控制台入口通过 |
| 本地样例 | 2 份合成文档生成 5 个片段；关键词检索与来源定位通过 |
| 模型接口 | 模拟 HTTP 端点覆盖 embedding、rerank、RAG 与 Agent；生成使用真实策略客户端的序列化和调用解析 |
| 本地 tokenizer | 原有 4B/9B 模板验收通过，只读 tokenizer，不加载权重 |

本轮没有运行真实模型推理服务，没有测得实际检索或问答准确率，也没有执行生产数据导入。测试中的生成和向量服务使用受控模拟端点；本地导入、正文关键词检索及已安装 wheel 则执行了真实文件流程。
