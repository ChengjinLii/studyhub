30 秒回答。 Hermes 正常通过 _build_system_prompt() 构建 system message，而 StudyHub workflow 又把同一文本作为 ephemeral_system_prompt 传入，导致每个模型请求看到两份训练策略。通过原始 rollout marker 审计定位后，保留 builder、清空 prompt cache 并将 ephemeral 字段设为 None；真实 Gate 的 118 条交互全部恢复为恰好一次，LoRA 也完成更新。

问题与影响

重复 system prompt 会浪费上下文，并可能非线性强化格式、停止和工具约束。即使 loss 或 Reward 看起来正常，也无法确认学到的是目标 policy，还是被重复提示扭曲的行为。因此原 Smoke checkpoint 只保留为诊断证据，不进入健康 Pilot lineage。
