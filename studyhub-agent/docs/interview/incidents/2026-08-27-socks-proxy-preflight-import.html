9B SFT 预检在加载本地 AReaL 配置链时失败。问题与模型、GPU 和训练数据无关，而是离线 Python 导入继承了服务器 SOCKS 代理，触发了 HTTPX 的可选依赖检查。

30 秒结论：服务器环境同时设置了 HTTP 代理和 ALL_PROXY=socks5://127.0.0.1:7892。AReaL 的日志依赖链加载 Trackio/Gradio 时，Gradio 在 import 阶段创建 HTTPX Client；HTTPX 发现 SOCKS 代理后要求未安装的 socksio，预检因此在 GPU 启动前退出。由于该预检只读取本地模型、数据和配置，最小修复是在导入 AReaL 前清除六个代理变量，而不是修改上游或安装无关依赖。

发生了什么

01 / LOCAL PREFLIGHT

加载 AReaL 配置

尚未启动 CUDA、模型或 optimizer。

02 / IMPORT CHAIN

Trackio → Gradio

gradio.processing_utils 在 import 时创建 HTTPX Client。

03 / ENVIRONMENT

HTTPX 读取 SOCKS

ALL_PROXY 指向本机 7892，但环境没有 socksio。

04 / FAIL CLOSED

训练未启动

错误被留在 preflight 阶段，没有占用共享 GPU。

竞争假设

排除

AReaL 安装损坏

清除代理后，同一解释器、同一 site-packages 可以正常 import。

部分事实，不是根因

缺少 socksio

确实未安装，但本地预检本不应建立 SOCKS transport；补包会掩盖边界错误。

根因

代理泄漏到离线阶段

进程继承 ALL_PROXY，让一个不需要网络的 import 进入可选 SOCKS 路径。

排除

GPU / FSDP 配置

最小复现只执行 import trackio，不触发 CUDA。

最小修复

预检内清理

preflight_runtime_sft_v3.py 在任何 AReaL import 前移除 ALL_PROXY、HTTP_PROXY、HTTPS_PROXY 及其小写变量。

启动器双保险

run_runtime_sft_v3.sh 在调用预检和 trainer 前执行相同清理。没有修改 AReaL、Trackio、Gradio 或 HTTPX。

为什么不装 socksio

安装可选依赖会让 import 通过，但离线训练仍会无意继承网络代理。正确修复是明确阶段边界。

为什么不全局删代理

只对当前本地训练子进程清理。需要联网下载或 Web rollout 的流程必须单独、显式配置 127.0.0.1:7892。

残余风险

依赖链可能变化

Trackio/Gradio 后续版本可能改变 import 副作用。Preflight 回归应继续验证：本地检查不建立网络 transport，也不启动 GPU。

60 秒回答9B SFT Gate 前，AReaL 配置预检在 Python import 阶段报 SOCKS 依赖错误。我先做最小复现，发现同一 venv 下保留代理时 import trackio 退出 1，清除代理后退出 0，因此排除了模型、GPU 和 AReaL 安装损坏。根因是离线预检继承了 ALL_PROXY=socks5://127.0.0.1:7892，Gradio import 时创建 HTTPX Client，触发了未安装的 socksio。修复是在 AReaL import 前局部清除代理变量，并在 launcher 做双保险，不修改上游也不安装掩盖问题的依赖。之后完整双 H100 Gate 完成一次优化器更新，初始和最终 LoRA hash 不同。
3 分钟追问这个案例的关键不是“缺包就装包”，而是先判断阶段语义。预检只读取本地配置、模型和数据，不应该因为 shell 的网络代理进入 HTTPX SOCKS 分支。我比较了四个假设：AReaL 损坏、socksio 缺失、代理泄漏、GPU 配置错误。无 GPU 的同解释器 A/B import 把根因缩到代理继承；socksio 缺失只是触发条件。最小修复只影响训练子进程，保留其他联网任务使用 7892 的能力。回归分两层：第一层是 import 前后 exit 1→0，并保存日志 hash；第二层是真实 9B Gate，验证 preflight、FSDP、assistant-only loss、checkpoint 导出和 LoRA 更新。边界是该 Gate 仍不证明模型质量，且未来联网 rollout 要有独立代理合同。
