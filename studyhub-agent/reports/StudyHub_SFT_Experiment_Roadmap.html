固定基座

02 / OBJECTIVE

固定训练目标

保持 assistant-only causal cross entropy，train_on_prompt=false。参数实验期间不同时引入加权 loss。

03 / RUNTIME

固定推理合同

统一 qwen3_5_nothink、cutoff 4096、BF16、greedy decoding；Router 与 Tutor 各自固定输出预算。

  • 同一生产 prompt 哈希与只读工具 schema

05 / GROUNDED TUTOR CONTROLLED STUDY

Grounded Tutor
边界证据实验

当前普通验证集已达到 120 / 120。新的评测重点覆盖证据删减、无关干扰、内容冲突和引用置换，并检查模型在证据不足时的回答边界。

T-CHALLENGE · 240 ITEMS

边界证据评测集

  • 40 条正常可回答，作为正常样本基线
  • 40 条 no-answer，答案不在证据中
  • 40 条 distractor，相关片段被无关内容包围
  • 40 条 conflict，不同资料给出冲突陈述
  • 40 条 partial，证据只支持问题的一部分
  • 40 条 citation counterfactual，置换 page / chunk / material_id
压力集按 material 与训练集隔离；模板生成器与训练样本分开。至少分层人工复核 20%，高风险边界样本全部复核。

四组配对比较

  • Base：原始 Qwen3.5-9B
  • Prompt：完整 grounded contract，无示例
  • Few-shot：每类提供 1 个短示例
  • SFT：当前与候选 LoRA，使用完全相同输入
按样本执行 paired bootstrap，并记录每类样本由失败转为通过、或由通过转为失败的数量。

07 / EXECUTION ORDER

分阶段
实验顺序

每批仅将通过 Gate 的候选送入下一批，以保留单变量解释并控制实验数量。

BATCH 00冻结评测合同建立两条任务的 challenge-dev v2；复核 Router final_holdout_v2 的 seal，为 Tutor 新建 sealed-test v2，并记录哈希与人工复核结果。0 training runs
BATCH 01补齐 BaselineBase、Prompt、Few-shot 与现有 SFT 在完全相同输入上推理，确认训练增益的真实起点。inference only
BATCH 02Router 参数筛选执行 R-OPT 与 R-LORA；每阶段只保留通过硬门槛的前一或两个候选。11 single-seed runs
BATCH 03Router 稳定性入选配置补齐另外两个 seed；未通过 Gate 时停止该阶段，不读取封存集。2 new runs
BATCH 04Tutor 压力实验先跑 T-CHALLENGE 与 T-BASE，再做小范围 T-OPT，最后补齐三 seed 和人工盲评。5 new runs
BATCH 05扩展归因执行 R-DATA、T-MIX 与 T-CONTEXT，形成数据效率、replay、状态和证据密度曲线。after core gate
BATCH 06一次封存评测配置、checkpoint 选择规则、代码 commit 和报告模板全部冻结后，Router 才打开现有 final_holdout_v2，Tutor 才打开新建的 sealed-test v2。single-use
