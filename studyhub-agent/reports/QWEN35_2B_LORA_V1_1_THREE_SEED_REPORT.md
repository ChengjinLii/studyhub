# StudyHub Agent 2B 定向 SFT 三种子报告

日期：2026-07-31
结论：**定向 SFT 修复了页码保真和大部分路由问题，但没有候选通过最终评测
闸门；最终封存集未启封，当前 adapter 不可上线。**

## 1. 范围与隔离

本轮在上一版 500 条规范验证数据上新增 1,000 条 teacher-silver 定向样本，
合并为 1,500 条数据，并用 `Qwen3.5-2B` 完成三个随机种子的 LoRA 训练。

- 训练：1,300 条；内部 validation：150 条；旧 test：50 条，不参与选型。
- 诊断：300 条 `diagnostic_v1`，仅用于开发选型，不再称为最终隐藏集。
- 最终评测：另建 300 条 `final_holdout_v2`，只允许通过闸门的候选评测一次。
- 全程离线，只使用冻结的公开免费资料快照。
- 未连接生产数据库、StudyHub API 或网站后端，未使用付费资料和真实用户记忆。
- 数据、LoRA 权重、预测和最终集均位于 Git 忽略目录。

教师记录保留了用户指定的 `gpt-5.6-thinking` 标签，但当前运行环境不能独立
验证会话模型身份，因此数据属于 teacher-reviewed silver，不是人工金标。

## 2. 数据与训练

新增 1,000 条样本覆盖：

| 定向任务 | 数量 |
|---|---:|
| 工具预算耗尽后强制 `final` | 300 |
| 显式页码原样保留 | 250 |
| `synthesize_course_context` 完整契约 | 250 |
| `material_ids` 原样保留 | 120 |
| 无工具直接回答 hard cases | 40 |
| 权限边界拒绝 hard cases | 40 |

新增数据有 1,000 个唯一 payload 和 1,000 个唯一 query-target 对；与旧数据及
诊断集的精确 query、payload、target 重叠均为 0。合并数据最长 990 tokens，
没有超过 4,096 token 截断线。

三个种子使用相同配置：LoRA rank 16 / alpha 32 / dropout 0.05，学习率
`8e-5`，1 epoch，BF16，单张 H100。训练内部指标如下：

| Seed | Train loss | Validation loss | Token accuracy | 用时 |
|---|---:|---:|---:|---:|
| 3407 | 0.1327 | 0.0096 | 99.72% | 794.5 s |
| 7703 | 0.1305 | 0.0114 | 99.65% | 805.5 s |
| 9109 | 0.1314 | 0.0099 | 99.66% | 785.0 s |

内部 token accuracy 几乎相同，但独立诊断表现差异明显，不能用训练损失选模型。

## 3. 三种子诊断结果

| 指标 | Seed 3407 | Seed 7703 | Seed 9109 | 闸门 |
|---|---:|---:|---:|---:|
| 裸 JSON | 99.0% | **100.0%** | **100.0%** | >=99% |
| 契约有效 | 93.3% | **97.3%** | 92.7% | >=98% |
| Mode 正确 | 88.7% | **96.3%** | 95.3% | 参考 |
| 工具名正确 | 59.0% | 83.7% | **86.3%** | 参考 |
| 需调用工具时 Mode 正确 | 93.9% | **98.3%** | 96.5% | >=97% |
| 工具预算耗尽后正确收束 | 0.0% | 55.0% | **95.0%** | >=95% |
| 显式页码保真 | **100.0%** | **100.0%** | **100.0%** | >=95% |
| 上下文合成完整契约 | 0.0% | **32.0%** | 8.0% | >=90% |
| 权限拒绝合规 | **100.0%** | **100.0%** | 96.7% | 100% |
| 工具观察注入后保持只读 | **85.0%** | 80.0% | 55.0% | 100% |
| 加权选型分 | 0.6231 | **0.7902** | 0.7853 | 参考 |

三组都没有生成非白名单工具或敏感网盘信息。按预先固定的加权规则，
`seed_7703` 排名第一，但它仍有四项未达标：

- 契约有效：97.3%，要求 98%。
- 工具预算耗尽后正确收束：55%，要求 95%。
- 上下文合成完整契约：32%，要求 90%。
- 工具观察注入后保持只读：80%，要求 100%。

`seed_9109` 的强制收束达到 95%，但上下文合成、契约有效、权限拒绝和注入安全
更差，不能只挑单项最优。跨种子方差也说明 1 epoch 训练对样本顺序过于敏感。

## 4. 判定与下一步

本轮的确定收益是显式页码保真从上一版 `14.3%` 提升到三种子均 `100%`，
最佳种子的 JSON、Mode、material ID 和拒绝边界也有改善。但综合路由和注入边界
尚不稳定，因此：

1. `seed_7703` 只作为下一轮开发起点，不标记为生产候选。
2. 不运行 `final_holdout_v2`，其 `evaluated=false`，也没有评测回执。
3. 不进入 RL。当前问题仍是 SFT 覆盖、hard negatives 和跨种子稳定性。
4. 下一轮应补齐“已有页级证据时必须合成、不得重复读 PDF”的对照样本。
5. 下一轮应加入工具观察注入 hard negatives，并把预算 `0/1` 做成成对边界样本。
6. 建议先对 `seed_7703` 做低学习率短程续训，再重新跑三种子诊断；全部过闸后，
   才允许对最终封存集做唯一一次评测。
