# StudyHub Agent 2B v1.3 状态归一化消融报告

日期：2026-07-31
结论：**v1.3 seed 7703 消融未通过双路径诊断门禁。停止三随机种子
扩展，不启封最终留出集，该 adapter 不可上线。**

## 1. 实验目标与隔离边界

v1.2 已证明，仅增加证据状态别名不能稳定解决路由冲突。v1.3 因此增加了一层
确定性的 `routing_state`：它只根据预算和已有工具观察生成统一状态，不读取标签、
模型预测、数据库或线上 API。状态包含：

- `must_finish_without_tools` 与 `budget_phase`。
- `evidence_phase`：未观察、待取证或可合成。
- `candidate_phase`：未观察、仅搜索结果或已查看详情。
- `memory_phase`：是否已读取当前用户学习记忆。

实验只使用冻结的公开免费资料快照和合成学习上下文。未访问生产数据库、生产
API、网站后端、付费资料或真实用户记忆；模型、数据和评测产物均位于 Git 忽略
目录。教师元数据保留用户指定的 `gpt-5.6-thinking`，但当前运行环境不能验证
会话模型身份，因此样本仍标记为 teacher-reviewed silver，而非人工金标。

## 3. 归一化本身的影响

先用未经续训的 v1.1 seed 7703 对同一诊断集做 A/B。只增加
`routing_state` 后，零预算收束由 `55%` 提升到 `65%`，直接回答由 `95%`
提升到 `100%`；但工具名由 `83.67%` 降至 `79.67%`，合成契约由 `32%`
降至 `12%`，注入后继续只读任务由 `80%` 降至 `65%`。

因此，状态归一化不能作为无需训练的独立修复；模型需要学习新字段，同时必须
保留旧输入路径和安全边界。

从原始 v1.1 `seed7703` adapter 续训，而不是从任一失败的 v1.2 adapter
续训。配置为 LoRA rank 16 / alpha 32 / dropout 0.05，学习率 `8e-6`，
1 epoch，BF16，单张 H100：

| 指标 | 结果 |
|---|---:|
| Optimizer steps | 203 |
| Train loss | 0.1762 |
| Validation loss | 0.0454 |
| Validation token accuracy | 98.88% |
| 训练用时 | 1,029.4 s |

新增 v1.3 验证集上，工具名正确率从 `82.78%` 提升到 `96.11%`，参数完全

`97.78%`。候选确实学到了新增结构，但该结果不能替代独立诊断集。

## 6. 失败归因

v1.3 成功学会了两项主要目标：原始路径 20/20 零预算场景正确结束，25 个合成
场景中 24 个选择 `synthesize_course_context`。但同时产生了新的任务冲突：

- 模型形成了过强的“收束”偏置。20 个观察注入后应继续安全只读工具的场景中，
  原始路径有 7 个、归一化路径有 8 个提前输出 final。
- 归一化输入的合成契约只有 17/25；新状态字段与原工具观察仍未形成稳定的一致
  决策规则。
- Material ID 完全保真分别降到 95/110 和 94/110，远超允许的 2% 回退。
- 直接回答出现损坏 JSON 或不完整 final 契约，原始路径为 18/20，归一化路径
  为 17/20。

这仍是 SFT 数据冲突、结构解码和运行时约束问题，不适合进入 RL。RL 会放大
当前的提前结束偏置，并不能自动恢复丢失的 Material ID。

## 7. 门禁决策

1. `eligible_for_three_seed_expansion=false`，不训练 seed 3407 和 9109。
2. v1.3 adapter 仅保留为失败消融，不修改 StudyHub Agent 的现有运行配置。
3. `final_holdout_v2` 保持 `sealed=true`、`evaluated=false`，没有评测回执。
4. 不进入 RL。下一轮应先增加同 payload 的“继续只读 / 必须 final”配对样本，
   并把 Material ID 与 final JSON 的确定性校验放到运行时契约层。
5. 在独立状态机一致性集通过前，不再扩大训练规模。
