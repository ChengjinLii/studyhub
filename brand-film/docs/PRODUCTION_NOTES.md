# StudyHub 品牌宣传片：制作说明

日期：2026-10-10。交付两个版本：

| 文件 | 画幅 | 用途 |
|---|---|---|
| `StudyHub_Brand_Film.mp4` | 9:16 竖屏，1080 × 1920 | 抖音、视频号、小红书等手机信息流（任务书默认规格） |
| `StudyHub_Brand_Film_16x9.mp4` | 16:9 横屏，1920 × 1080 | B 站、官网、活动大屏 |

两个版本共用同一套时间表、配乐和音效，时长都是 30 秒，30 fps，H.264 + AAC 立体声。

## 1. 创意

**一页笔记的旅程。** 一张笔记卡贯穿全片：群里没人回应的“求资料”，汇聚成 StudyHub 里有序的课程资料；资料被搜到、被下载；同学把自己的笔记投稿；这份笔记一分为多，飞向一圈圈同学，同学的眼睛变成笑眼；最后笔记的两条横线竖起来，变成 StudyHub 机器人 Logo 的两只眼睛。

**品牌依据。** 主 Logo 是仓库里的机器人图标（`frontend/public/icons/studyhub-app.svg`：深色圆角方块 + 两只白色胶囊眼）。全片角色都用同一个“胶囊眼”造型；笔记的文字行也是胶囊。所以形变可以一直留在“圆 → 胶囊 → 卡片 → 页面 → Logo”这一组圆角矩形里，轮廓不会打结。色板取自 `frontend/styles/globals.css`（品牌蓝 #2563eb、墨色 #0f172a、浅底 #f4f6fb），辅以官网编辑风的青绿、机器人学士帽流苏的琥珀色。

**风格融合。** Flat Vector（`mg-styles-15` 01）提供纯色平涂、几何角色、弹性入场、错峰 2–4 帧、元素带动的色场擦除；Shape Morph（08）提供“A → 圆/胶囊 → B”的中介形变、形变中 10–15% 挤压拉伸、每次落位卡在拍点上。参考项目的品牌、文案、场景和代码都没有使用。

**核心记忆段落。** 15–20 秒：“一个人的积累 → 变成更多人的帮助”。26.2–27.0 秒：笔记变成 Logo，表达“让知识，因为分享而产生更多价值”。

## 3. 数据依据

- 片中数字采用委托方提供的历史口径：370+ 位用户、260+ 份学习资料、1800+ 次资料下载，标注“历史运营数据”和“历史累计数据，非实时统计”，不推算增长。
- 2026-10-09 约 21:00 实测公开接口 `GET https://study-hub.cn/api/materials?size=1`：用户 378、资料 259（其中可见 247）、下载 1872。该接口的“已上架”计入隐藏资料，“用户”为全部账号，口径与任务书不一致，所以没有替换。
- 仓库 `/join` 页快照（截至 2026-09-08）：用户 362、上架资料 190、下载 1778，口径又不同，不混用。
- **需要委托方确认：** 任务书的“260+ 份学习资料”高于目前任何公开来源（259 / 247 / 190）。片中按任务书保留并标注为历史数据。
- 访问入口：`https://study-hub.cn` 于 2026-10-09 实测 HTTP 200、证书有效。`www.study-hub.cn` 证书不覆盖，片中不使用。片中没有二维码。

## 4. 产品表述核对

- 手机界面里的文字全部来自真实前端（核对文件见 `docs/storyboard.md` §3 与审阅记录），例如“资料库”“搜课程 / 资料名 / 标签”“获取免费链接”“下载已开始”“投稿工作台”“选择 / 拖拽 文件”“提交资料”“投稿成功，文件安全检查中”。
- 演示的下载对象是免费资料，用户处于登录状态。网格和列表里同时出现付费资料（真实价格格式 ¥x.xx），避免暗示“所有资料免费”。
- 片中没有“所有资料免费”“积分”“海量”“无限下载”“保证高分”等说法。

## 5. 技术方案

- 画面：`src/film.html` + ES 模块。`window.renderFrame(t)` 只依赖 t 生成整帧 SVG；无随机数、无系统时间、无 CSS 动画。`render/render.mjs` 通过 puppeteer-core 驱动本机 Chrome，经本地 HTTP 服务加载页面，逐帧截图。
- 运动模糊：每帧 16 个子帧（180° 快门），ffmpeg `tmix` 平均；全屏色场擦除和 Logo 落地帧不加模糊（`cues.json` 的 `blur.off`）。
- 声音：`audio/compose.py` 用 numpy 合成全部配乐（120 BPM，C 大调，C–G–Am–F）和音效；时间点从 `cues.json` 读取，并输出 `cue_report.json`。
- 编码：H.264 High、yuv420p、BT.709（矩阵、原色、传递特性均已标注）、CRF 16；AAC-LC 256 kb/s、48 kHz 立体声；两遍 `loudnorm`（−14 LUFS，真峰值目标 −2 dBTP）。
- 渲染时间（Apple M4）：每个版本约 9.5 分钟（16 子帧 × 900 帧 = 14 400 张截图）。
- 回归测试：`tests/test_tooling.sh`（片段帧边界、静帧重名、检测脚本文件名转义），3/3 通过。

## 8. 审阅过程

审阅报告与每轮任务说明在交付包 `reviews/`；修复与未处理事项汇总在 `docs/review_backlog.md`。

1. 每个场景由独立的构建代理按分镜实现，用静帧检查交接帧（逐像素一致）和形变中间帧。
2. 竖屏 v1 成片：独立 Opus 审阅，1 项阻塞（S2 字标越出右侧安全区 27 px），另有 8 项可改进项。修复轮全部处理。
3. 竖屏 v2 复审：11 项修复全部核实，没有引入新的阻塞项。
4. 横屏 v2 成片：独立 Opus 审阅，无阻塞项；其中 4 项小问题在最后一轮润色中处理。
5. 代码：独立 Opus 审阅无阻塞项；Codex 审阅 2 项 P1、1 项 P2（只影响片段和静帧工具，不影响整片），已修复并各加一条回归测试，Codex 复审无问题。
6. 最后一轮润色（横屏 4 项、去掉开头的孤立气泡音）之后，由制作方核对改动帧并重做成片检测，没有再开独立复审。

## 9. 已知不足

- **数据口径待确认**：“260+ 份学习资料”高于目前公开来源（259 / 247 / 190），见第 3 节。
- **快速运动的子帧痕迹**：手机退场（14.4–14.5 s）、M5、M9 等最快的移动在全分辨率静帧上可见相距约 5–6 px 的子帧副本；按 30 fps 播放时读作运动模糊。
- **数据停留段近乎静止**：竖屏 23.5–25.5 s 只有极小的动作，用来留出读数时间。
- **界面是简化示意**：详情页评分用“评分：4.8”文字表示（真实详情页为星级）；手机底栏统一用五栏导航（真实详情页底栏不同）；任务书允许简化。
- **点击音**：三种点击声中，软点击与卡片点击听感较接近。
- **横屏手机界面字小**：最小界面文字约 16–20 px，在手机上横屏观看偏小；步骤条承担主要信息。
- **配乐与音效为程序合成**：版权干净、与画面逐帧同步，但质感不如专业作曲与录音。如需商业投放，可替换为授权音乐（时间表不变）。
- **未做人工试听**：制作方无法直接收听，声音质量依据频谱、波形、响度和同步测量判断；建议上线前人工试听一次。
