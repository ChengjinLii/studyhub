01 / TASK

一个 Agent，
两种工作。

最先确定的不是模型大小，而是输出契约。Router 面对的是有限动作空间和严格参数；Tutor 面对的是较长的证据、解释和学习建议。把两者混成一个 SFT 任务，会让数据目标与评测指标同时失焦。

CONTROL PLANE

Router 2B v1.7

Qwen3.5-2B · LoRA r16 · seed 7703
  • 输入用户请求、上下文、预算、工具观察
  • 输出tools / final 严格 JSON
  • 学习内容工具选择、参数、继续或停止
  • 任务族12 类路由与边界场景
  • 模型规模合并后 2.213B 参数
KNOWLEDGE PLANE

Grounded Tutor 9B

Qwen3.5-9B · LoRA r16 · seed 6209
  • 输入学习问题、资料正文与页级证据
  • 输出带引用的 final JSON
  • 学习内容讲解、比较、复习计划与依据
  • 任务族10 类证据讲解场景
  • 模型规模9.453B 参数

边界也在任务定义中。Router 的安全参数不是自由文本创作：只读工具白名单、调用预算、可信资料 ID、明确页码和权限拒绝都能由确定性程序检查。Tutor 则只能使用提供的免费资料证据，引用必须能回到具体资料与页面。两条任务线因此拥有不同的数据组织方式和验收合同。

02 / DATA

先建立边界，
再增加样本。

训练语料属于教师审校 Silver：标签由规则与教师模型构造后审查，不冒充人工金标。资料来源限定为公开免费资料和预览内容；空目标、重复行和跨集合泄漏在训练前完成审计。

配比承担的是能力保留。Router 在补充注入恢复、状态迁移和个人记忆时，同时保留直接回答、基础搜索、资料 ID、页码、强制收尾和权限拒绝 replay，避免新任务挤掉旧路由。Tutor 的训练、验证和封存集合则按资料隔离，而不是随机拆行，以检验跨资料泛化。

模型看到什么，

模板、Tokenizer 和 label mask 是训练合同的一部分。训练与评测使用同一套 Qwen chat template，避免把模板差异误判为模型能力。

04 / MODEL & TRAINING

容量服从任务，
LoRA 控制改动。

2B 用于有限动作与结构化路由，9B 用于长证据综合。两者都从本地 Qwen3.5 基座开始，以 BF16 LoRA 训练；本轮没有使用 QLoRA，NF4 只在训练完成后作为推理对照。

LoRA 的意义不只在于减少可训练参数。Adapter、合并模型和量化模型是三种不同的推理产物，必须分别检查输出合同。训练配置、模型 revision、adapter 哈希和运行环境都被记录，确保后续评测指向同一个模型状态。

05 / CURVES & EFFICIENCY

曲线负责诊断，
任务负责验收。

两条任务线均正常收敛。曲线用于发现发散、过拟合和 checkpoint 位置；最终效果仍由生成式评测决定。

Router 2B · train / validation loss

Validation loss 从 0.07315 降至 step 184 的 0.04360，step 185 为 0.04372；validation token accuracy 为 98.95%。最低 loss checkpoint 另做生成式诊断后，仍在预算收尾和注入恢复上暴露失败。

Grounded Tutor 9B · train / validation loss

Validation loss 从 0.22853 降至约 0.186，后半程保持稳定。独立验证 120/120 严格通过，封存集合为 119/120。

GENERALIZATION

看未见表达，也看完整状态路径

Router 诊断与训练 query 精确隔离，并同时覆盖两种输入表示；Tutor 验证和封存按资料隔离。当前两条 SFT 运行各使用一个 seed，因此曲线和 Gate 描述的是已保存模型，不把单 seed 结果外推为方差结论。

RETENTION

新能力不能挤掉旧路由

Replay 保留基础搜索、直接回答、权限拒绝、页码、资料 ID 和预算收尾。Router 的原始生成在注入恢复上仍为 0%，说明 SFT 对部分边界的学习不足；运行时投影能约束动作，但原始策略仍需独立观察。

07 / INFERENCE ENGINEERING

同一组权重，
可以有不同表现。

Adapter、合并 BF16 与 NF4 量化不是同一个交付物。对 Tutor 9B 的三种形态进行了相同的生成式验证，比较严格通过率、峰值显存和吞吐。

推理形态严格通过峰值显存生成吞吐观察
Base BF164 / 12021,232.6 MiB152.46 token/s未获得任务能力
LoRA BF16120 / 12021,399.2 MiB86.49 token/sAdapter 直接加载
Merged BF16120 / 12021,232.6 MiB139.98 token/s质量保持，吞吐更高
Merged NF4116 / 12010,800.9 MiB80.86 token/s显存下降，同时出现 4 条合同失败

这个对照说明，量化不能只报告显存。NF4 将峰值显存降到约一半，但严格通过率从 120/120 变为 116/120；合并 BF16 则保持全部验证样本通过，并减少 Adapter 动态加载开销。输出 token 预算也属于推理配置：Tutor 封存集合唯一失败是回答在 768-token 上限处截断。

08 / CONCLUSION

训练结果，
要按任务解释。

SFT 已经建立了两个清晰的能力起点。Tutor 学会了基于资料证据生成结构化讲解；Router 学会了多数基础路由，但其原始提案在复杂参数和边界状态上仍有明显误差。

ROUTER

结构化拟合很好，语义边界仍难

Validation loss 0.04372、token accuracy 98.95%，但原始生成在预算收尾、页码、资料 ID 和注入恢复上没有达到合同阈值。Teacher-forcing 指标与完整动作正确率不能互相替代。

TUTOR

证据讲解形成稳定基线

独立验证 120/120，按资料隔离的封存集合 119/120；唯一失败来自 768-token 截断。Merged BF16 保持全部验证样本通过，NF4 则引入 4 条合同失败。

ENGINEERING

确定性合同与模型判断分层

JSON、schema、只读权限、可信 ID 和页码范围由投影层检查；模型保留工具语义、证据顺序与终止判断。原始提案和可执行动作同时留存，便于归因。

完整闭环由这些部分共同构成：清晰的任务合同；可追溯的数据来源与标签等级；职责明确的训练、验证和封存集合；跨资料、模板与 payload 的泄漏检查；主任务、难例和 replay 的数据配比；一致的 chat template 与 tokenizer；只监督 assistant target 的 label mask；与任务复杂度匹配的基座；LoRA 配置和推理形态对照；学习率、batch、seed 与 checkpoint；显存、时长和吞吐；训练与验证曲线；生成式业务评测；跨表达和状态路径的泛化；旧能力保留；输出预算、约束解码与量化；最后是配置、环境和哈希记录。
